# Dodo features — backend and app

Moved here from the root `CLAUDE.md` on 2026-10-22 (it was over the instruction-size limit). Paths are relative to the repo root. The iOS build/install playbook is `apps/feynd/CLAUDE.md`; the "spec first, then verify behavior" gates and where the Swift code lives stay in the root `CLAUDE.md`.

## Dodo voice (GPT-Live) — the non-default engine since 2026-09-21

ElevenLabs + Claude (next section) is the default in Dodo and Polly; GPT-Live is the other choice in Profile → Voice → Voice engine. Dodo's voice surfaces — Talk to Dodo (global / topic), spoken flash rounds, the Final Review, the Second Chance and the recert refresher — run on **OpenAI GPT-Live (`gpt-live-1`)** since 2026-09-11 (they were on Realtime `gpt-realtime-2.1` before). Code: `src/lib/f2/live.ts` (prompts + session config + the OpenAI call), `src/app/api/f2/live/session/**` (start = SDP exchange, finish = transcript), `src/lib/f2/realtime.ts` (voice-session rows, prefs, the voice catalog — shared), `apps/feynd/Feynd/LiveVoiceClient.swift` (the screens in `VoiceSessionView.swift` / `FlashVoiceView.swift` are unchanged), `apps/f2/schema/007_f2_voice_sessions.sql`. Reference: [`docs/f2-gpt-live-reference.md`](docs/f2-gpt-live-reference.md).

How it is shaped: the live model owns the conversation (full duplex — it listens while speaking and handles interruptions itself; there is no turn loop, no commits, no `response.create`) and gets a short prompt with the script, a ≤24K-char excerpt of the material and a delegation policy; a **Responses backend** (`gpt-5.6-luna`, env `OPENAI_LIVE_BACKEND_MODEL`) gets the FULL material in its own prompt and the live model delegates to it for details and fact checks. No function tools on the client. The phone's WebRTC SDP offer goes through our server to `POST /v1/live/sessions` — there are no ephemeral client secrets for Live. Transcripts arrive as timestamped fragments per speaker; the client groups them into turns for the graders.

Verify with `npx tsx scripts/test-live-dodo.ts [mode] [--nudge] [--answer "…"]` (headless: the exact server session over WebSocket, answers with macOS `say`, prints transcripts + delegations) and the simulator drill `-VoiceLiveTest 1` (see `apps/feynd/CLAUDE.md`). The legacy `/api/f2/realtime/session` + `/tool` routes stay only for Dodo builds older than 0.2 (106). **Peri (`src/lib/f4`) and Loci still use Realtime** — `docs/f2-realtime-api-reference.md` covers those.

## Dodo voice, ElevenLabs + Claude — built 2026-09-20, the default since 2026-09-21

A per-device setting and **the default** (`VoiceEngine.fallback`; a device that never touched the picker gets it): Profile → Voice → **Voice engine: ElevenLabs + Claude / GPT-Live** (`VoiceEngine` in `apps/feynd/Feynd/DodoVoiceClient.swift`, UserDefaults `voiceEngine`). The voice stack therefore depends on the Mac mini's bridge being up. Same five voice surfaces, same screens, hold-to-talk, finish route and graders. Reference: [`docs/f2-eleven-voice-reference.md`](docs/f2-eleven-voice-reference.md); setting it up on another machine, moving the bridge, the Vercel vars and a what-broke table: [`docs/f2-eleven-voice-setup.md`](docs/f2-eleven-voice-setup.md).

**ElevenLabs Speech Engine** owns the audio (speech-to-text, turn-taking, barge-in, the voice — Jessica on `eleven_v4_turbo` with expressive mode off since 2026-10-09; the v3 conversational model with expressive mode on performed every line and Bart stopped enjoying voice mode over the mannerisms — only the engine's `tts` block in `apps/dodo-voice-bridge/engines.mjs` changes how Dodo sounds, never `turn` / `cascade_timeout_seconds` / `conversation`); **Claude Opus 5.5** writes every turn. Speech Engine is bring-your-own-LLM and it connects *to us* over a WebSocket, which Vercel cannot host, so `apps/dodo-voice-bridge` (a small Node process on Railway) takes each transcribed turn and POSTs it to `/api/f2/eleven/turn`, where Claude streams plain text back to be spoken. The bridge is a dumb pipe, like the iMessage agent: prompts, tables and the Anthropic key stay on Vercel. Code: `src/lib/f2/eleven.ts` (token mint, the turn), `src/lib/f2/voice-start.ts` (mode gates + script, shared by BOTH engines — change a gate there, not in a route), `src/lib/f2/live.ts` (`engine: 'eleven'` swaps the persona for a text-to-speech one, gives Claude the whole material instead of an excerpt, and drops the delegation policy), `apps/feynd/Feynd/ElevenVoiceClient.swift` (ElevenLabs' Swift SDK, which rides on LiveKit — its WebRTC build has prefixed symbols and links next to ours).

It is a cascade, not full duplex: no backchannels, and ≈ 2 s from the end of the user's turn to Dodo's first sound (Claude's first token is about half of it; thinking runs adaptive at low effort because Opus 5.5 cannot switch it off — 1.4–1.6 s to first text headless, 2026-09-22). Barge-in stops Dodo in about a second and the transcript keeps what was actually spoken. Dodo speaks first in scripted modes because the client sends a `[begin]` text message the server swaps for the opening instruction.

Two engines on ElevenLabs because an engine has one `ws_url`: "Dodo (dev)" → bridge `/ws/dev` → `localhost:3100`; "Dodo" → `/ws/prod` → `feynd.cc`. `ELEVEN_SPEECH_ENGINE_ID` is the dev one in `.env.local` and the prod one on Vercel; `DODO_BRIDGE_SECRET` and `ELEVENLABS_API_KEY` must be on Vercel too. The bridge runs on **Railway** since 2026-09-21 (project and service `dodo-voice-bridge`, `https://dodo-voice-bridge-production.up.railway.app`, a permanent hostname the four engines were pointed at once; ship a change with `railway up --ci --service dodo-voice-bridge` from the folder). It spent its first day on Bart's MacBook Air and an afternoon on the Mac mini behind Cloudflare quick tunnels; the mini's launchd job is uninstalled, the Air's is not — its old `run.sh` re-points all four engines at the Air if it restarts while the Air is awake (see the bridge README). A dev machine's `run.sh` now re-points only the two dev engines. If Dodo says "Voice failed" on this engine, `railway logs` from `apps/dodo-voice-bridge` first. tunn3l's HTTP mode does not pass WebSocket upgrades, hence Cloudflare for dev machines.

Verify with `npx tsx scripts/test-eleven-dodo.ts [mode] [--interrupt]` (headless: real route, spoken answers through ElevenLabs' speech-to-text, a barge-in) and the simulator drill with `-voiceEngine eleven` added (see `apps/feynd/CLAUDE.md`). In the simulator run it with `-voiceHoldToTalk 1`: the sim listens through the Mac's real microphone, and room noise (or the Mac's own speakers) keeps interrupting a hands-free session until nothing gets said.

**Polly has the same engine, also the default, for every voice mode** (2026-09-21; phase 1 on 09-20 was conversations only): the clean-up walk's "next card" and the level check's silence nudge are text messages from the app (`ELEVEN_CUE_PREFIX` = `[app] `, which `turnMessages()` hands Claude as a note from the app and clients keep out of the transcript). Same switch in its Profile → Voice, `ios/Polly/ElevenVoiceClient.swift` and `/api/polly/eleven/{session,turn}` in the polly repo (`../polly`, since 2026-09-30), its own two engines on the bridge (`/ws/polly-prod` → polly-iota.vercel.app, `/ws/polly-dev` → localhost:3101, a multilingual voice). See the polly repo's `CLAUDE.md`.

## Peck or Perish and Deep Dive — the rest-stop minigames (2026-09-23, 2026-10-02)

Clearing a Peck rest stop (5, 15, 25, …; `PeckMilestone.isRest`) for the first time opens its minigame once the results cover closes; a cleared rest stop's signpost ("▶ play again") replays it. Which game is `PeckMilestone.restGame` (mirrored by `restGame()` in `src/lib/f2/peck-game.ts`): **Peck or Perish** at 5, 25, 45, …; **Deep Dive** at 15, 35, 55, … — a big payoff or game every five levels, with the level-10 film in between.

**Deep Dive** (`apps/feynd/Feynd/DeepDive{Engine,Art,Audio,View}.swift`, ported from the chosen web concept `public/dodo/level15/deep-dive.html`, which stays as the design reference next to the runner-up Pebble Skip): the dodo in a bubble helmet dives into Jelly Lagoon — hold to sink and steer, let go to float; pearls +3, gummy jellyfish cost 11 air and bounce you up, rising bubbles bump, dashed air pockets refill 40; the air lasts 32 s of diving; score = deepest metre + 3 per pearl, posted to the same board route as `{ score }` (the `best_year` column holds it for these levels; `validScore` picks the range per game). Water darkens and starts to glow with depth; kelp, caustics, a night-lagoon surface with lanterns and lily pads. Sound: `DeepDiveAudio` — a looping lagoon pad whose lowpass closes with depth plus jelly one-shots from `JellySynth` on four rotating players. **The game class is a plain class, not @Observable:** the Canvas mutates it every frame and an observable game re-invalidated the canvas on every write (1,400 redraws a second, a frozen UI); the view keeps `@State` for phase and board, fed by `onPhase`. Hooks: `-PlayPeckGame 15 -DeepDiveScene dive|deep|end -PeckGameMockBoard 1`. **Dev mode** (2026-10-02): admins (`f2_users.is_admin`, schema 054 — Bart only; `getSessionUser` returns it, the app's `F2User.isAdmin`) get a Developer section in Settings with a Dev mode toggle (UserDefaults `devMode`) that opens every rest-stop game and the film from the map, cleared or not; the board route still refuses scores for uncleared levels (403), which the game shows as its board note. Rats, pigs and monkeys off the Dutch ships run at the dodo's one egg on Mauritius in 1598; each bite raises P(extinct), and at 100% the score is the year the dodo went extinct (history: 1662). Look: a 1600s naturalist engraving printed in riso inks (paper, black hatching, pink / marigold / teal multiplied slightly off register), Ultra + IM Fell English fonts bundled in `Feynd/Fonts/`, synthesized marimba sound.

- **Native** (`apps/feynd/Feynd/PeckGame*.swift`): Engine = rules only, Art = SwiftUI Canvas drawing on a fixed 400 × 720 logical canvas, Audio = one AVAudioSourceNode with the sequencer in the render callback (ambient session; never switches a live `.playAndRecord`), View = scaling + input + board calls. iPhone scales to fit, iPad caps at 1.4×, Catalyst holds 1.15× (shrinks only when the window is too short). The printed background is rendered once per scale with ImageRenderer; per-frame caches live in a reference type because a Canvas closure never sees @State values set after the first body.
- **Board**: `f2_peck_game_scores` (schema 053, applied), `src/lib/f2/peck-game.ts`, `GET|POST /api/f2/peck-game/<level>` (POST `{ year }`, 403 unless the player has cleared that level). Handles are the username's part before "@" (guests: "guest 1a2b"). Check: `npx tsx scripts/f2-peck-game-check.ts` (env loaded; writes and removes rows for the two test accounts at level 995).
- **Tuning**: the numbers came from a bot on the web prototype (`public/peck-or-perish/`, local only, not committed): a casual player dies around 1670, a sharp one around 1700, rounds run 70 to 110 seconds.

## Dodo Actively Read — the daily pick with a test inside the conversation (2026-10-07)

Once a day each user gets one random topic of theirs that isn't Actively Read yet (stars = 0) and isn't declined: an iMessage at the user's daily send time (anyone with a paired handle and **Today's read** on in Settings — until 2026-10-16 it rode on the daily card, then on the card OR the voice checkin; "Reply 2" = not interested), a push (APNs, new — `src/lib/f2/push.ts`, at most one a day, collapse id `dodo-daily`), and the top banner in the app's one banner slot (`HomeBannerSlot`: today's read > Peck streak at risk > this week's refresher; dismissing shows the next). The link (`feynd.cc/read/<id>`, universal link) and the push open an `actively_read` voice session (`buildLiveActivelyReadInstructions` in `live.ts`): Dodo talks it through, "I'm ready" starts exactly three questions with no hints, "not interested" ends it. Graded after End by `judgeActivelyRead` (flash.ts: outcome tested/declined/conversation, A+…F; passing = all three answered and B+ or better (lowered from A- on 2026-10-09) — the first-star bar, real understanding, not mastery); a pass gives star 1 and clears the next Peck level as if played (`awardActivelyRead`: passing set row with the level's XP × streak, weekly streak marked, once per topic). State: `f2_users.actively_read`, `f2_threads.ar_inactive_at` / `ar_passed_at`, schema 055. **Sent at the user's one daily send time** (Settings → Daily card → Send at, schema 057, 2026-10-16; its own toggle **Today's read** there too) by the hourly `/api/f2/daily/tick`; `/api/f2/actively-read/nudge?force=1&user=<id>` sends one user theirs now. Checks: `npx tsx scripts/f2-actively-read-check.ts [--voice]` (pick, "2", undo, award; three simulated conversations through the real voice model and grader) and `scripts/f2-actively-read-prod-check.ts` (the same through production's routes, test account, restored), `scripts/f2-push-check.ts`.

## Dodo Daily Voice Checkin — one question a day, pass/fail, a second chance (2026-10-12)

Beside Actively Read (above) and the daily card: at the user's daily send time every user with the Settings toggle on (**Settings → Daily card → Daily voice checkin**, `f2_users.voice_checkin_enabled`, default on, needs a paired handle like the card) gets one iMessage with ONE high-level question about one random *active* topic — any kind, starred or not — and a universal link (`feynd.cc/checkin/<id>`) into a `voice_checkin` voice session (`buildLiveVoiceCheckinInstructions` in `live.ts`): Dodo asks exactly that question, says "Pass." or "Not yet." out loud; on a fail it explains the idea (30–60 s) and asks once more, and there is never a third ask. **The bar (2026-10-19, between the old gist check and Actively Read's B+):** the FIRST answer must give the main idea plus one reason, mechanism or example from the material, in the user's own words (Dodo asks one "why?" / "an example?" follow-up inside that attempt when only the gist comes); the second chance is for learning only — getting it after the explanation is a fail with `second_ok`. **A pass marks the topic Actively Read** (`awardActivelyRead`: star 1 + the next Peck level, once per topic). After End `judgeVoiceCheckin` (flash.ts, Opus against the source) grades the transcript pass/fail/no_answer/inactive and `recordVoiceCheckin` settles the day once: an attempt bumps the daily streak like a daily-card answer (so the quiz toggle can be off and the streak lives on the checkin), pass pays 15 × multiplier XP, fail 5. **Reply 9** to the text (or "done with this topic" in the chat, or the Rename sheet) sets the topic type **Inactive** (`kind = 'inactive'`, schema 056): out of the checkin, Actively Read, daily-card and Peck pools, chat and stars kept; any other type brings it back. The question is written by Sonnet 5.5 at pick time (`writeCheckinQuestion`: main idea / argument / why, never a date, name or number) and stored in `f2_users.voice_checkin` with the day's state. Sent at the user's one daily send time by the hourly `/api/f2/daily/tick` (schema 057, 2026-10-16 — it was a 5 pm PT cron before); `/api/f2/voice-checkin/nudge?force=1&user=<id>` with the cron secret sends now. Routes: `GET|POST /api/f2/voice-checkin` (today's checkin / mark inactive), `POST /api/f2/topics/[id]/voice-checkin` (grade). Check: `npx tsx scripts/f2-voice-checkin-check.ts [--voice]` (pick + question, "9" through the iMessage gate, the three pools, recording once a day; `--voice` runs a first-try pass, a gist-only answer (follow-up, then not a pass), a second-chance answer (a fail with `second_ok`) and a two-miss fail through the real engine and grader). Simulator: `-OpenVoiceCheckin <topic id>` and `-MockCheckinResult passed|second|failed|no_answer|inactive|grading`.

## Dodo daily texts — one send time (2026-10-16)

The three daily texts (the daily card, Today's read, the Daily Voice Checkin) each have a toggle under **Settings → Daily card**, and one **Send at** hour under them: `f2_users.daily_hour` (0–23) in `daily_tz` (an IANA zone the app sends from the device whenever the sheet loads or the hour changes; schema 057, defaults 9 and America/Los_Angeles). One Vercel cron, `/api/f2/daily/tick` every hour on the hour, finds the users whose local hour is now (`dueUsers` in `src/lib/f2/daily-time.ts`) and runs the three senders for them in that order — card, read, checkin — because over iMessage the text that went out last owns a "2" or a "9" (agent.ts). The old fixed crons (9 am / noon / 5 pm PT) are gone; their routes stay for manual sends (`?force=1&user=<id>`). Checks: `npx tsx scripts/f2-daily-time-check.ts` (pure: hours across zones and DST, one due hour a day) and `npx tsx scripts/f2-daily-settings-check.ts` (the profile route and the tick against a local dev server, test account only). **Dodo's voice** the same day: River ("relaxed, neutral, informative") at stability 0.75 on the production engine, and the spoken persona told to be matter-of-fact with no praise words — Bart found Jessica grating and too enthusiastic even on v4 turbo. Still too eager that afternoon, so **Profile → Voice → Dodo's voice** (2026-10-16, build 135): Angela, Sarah or River, Calm or Normal (per device, UserDefaults `elevenVoice` / `elevenStyle`, default Angela Calm, which old builds also get). One production Speech Engine per pair, all on the bridge's `/ws/prod` (`engines.mjs` makes them; new engines are capped at 2400 s); `dodoEngineId()` in `eleven.ts` maps the app's `eleven_voice` / `eleven_style` to the ids (production only; dev keeps `ELEVEN_SPEECH_ENGINE_ID`). Normal = v4 turbo, Calm = `eleven_turbo_v2` (0.34 s to first sound; multilingual v2 sounds the same family but takes 1.45 s). `scripts/test-eleven-dodo.ts` connects to the engine named by its own `ELEVEN_SPEECH_ENGINE_ID`, not the route's pick, so name the variant's id to test one.

## Dodo global chat — one conversation across all of a user's topics (2026-09-20)

**Hold the + on the Topics screen** → a pill, "Ask across all topics" → a full-screen chat (`apps/feynd/Feynd/GlobalChatView.swift`) with a composer and a mic; typed and spoken turns are one thread (`f2_global_chats`, a global voice session's transcript is appended when it ends), and chips under an answer name the topics it drew on. Reference: [`docs/f2-global-chat.md`](docs/f2-global-chat.md).

The knowledge behind it (`src/lib/f2/knowledge.ts`, schema 051) is two layers, because a big library is millions of characters: a **digest card per topic** (Sonnet 5.5, rewritten when the material's hash changes) — all of them, with the learner's standing on each, are the map in every global prompt — and the **material chunked + embedded** (OpenAI `text-embedding-3-small`, pgvector) and searched per turn, vector + full text, ALWAYS inside that one user's rows, with a similarity floor so an off-library question finds nothing. `runGlobalTurn` (`src/lib/f2/global-chat.ts`) retrieves for the question first, then runs Claude with the map, the passages and a `search_material` tool; the typed chat uses it on Sonnet 5.5, global VOICE on the ElevenLabs engine uses the same function on Opus 5.5. On GPT-Live, global voice only gets the map (compact in the live prompt, full in the backend) — no passage search. Material writers schedule a re-index (`knowledge-hooks.ts`); opening the chat and a nightly cron (`/api/f2/knowledge/backfill`) catch up what they miss. Check: `npx tsx scripts/f2-global-chat-check.ts` (guests — and every guest sign-up texts Bart, so run it sparingly).
