# The night town: the API

A town on a 48 x 32 grid of 20-pixel tiles, drawn on one canvas (960 x 640). `core.js` holds the clock, the
map and the shared state; every feature is one file in `parts/` that calls `town.register`. Parts are loaded
in file-name order; `parts/index.js` (the list) is regenerated by the harness, never edit it.

## A part

```js
// One line: what this part is. (The first line of every part says what it does.)
town.register({
  name: 'bakery',          // unique; town.state.parts.bakery is this part's own data, an object, already there
  order: 50,               // when init/tick run (low first). ground 0, road 10, houses 20, people 30; yours 40 to 90
  layer: 40,               // draw order (low first). Under 100 is darkened at night; 100 and up draws on top (lights)
  init(town) { },          // once, at start
  tick(town, dt) { },      // every step; dt is in hours (0.05 = 3 minutes)
  draw(ctx, town) { },     // every frame; ctx is a 2D canvas context, tile (x, y) is at pixels (x*20, y*20)
})
```

## Shared state (`town.state`)

- `time`: `{ hours, day, hour, night, light }`. `hours` counts from the start (day 1, 06:00); `hour` is 0 to 24;
  `light` is 1 by day, 0 at night, between at dawn and dusk; `night` is `light < 0.5`.
- `tiles[y][x]`: a string: `'grass'`, `'road'`, `'building'`, or any new kind a part sets (`'water'` and `'wall'`
  block walking).
- `buildings`: `{ id, kind, name, x, y, w, h, color, door: { x, y } }`. The door is the tile just below the
  building's bottom edge, on the road.
- `people`: `{ id, name, home, x, y, path, doing, visible, speed, color }`. `home` is a building id; `x, y` are
  tile coordinates (fractions while walking); `doing` is a word (`'home'`, `'walking'`, `'idle'`, `'going home'`,
  or a new one); `visible` false means inside; `speed` is tiles per hour.
- `events`: `{ hours, day, kind, text }`, the last 300 things that happened.
- `parts[name]`: each part's own data.

## Helpers

- `town.C`: the colors `cream ink red blue yellow lime`; `town.mix(a, b, t)` blends two of them. Use only these.
- `town.rand()`, `town.randInt(a, b)`, `town.pick(list)`: seeded random. Never `Math.random`.
- `town.at(x, y)`, `town.set(x, y, kind)`, `town.walkable(x, y)`, `town.inside(x, y)`.
- `town.findSpot(w, h)`: a free spot of grass with the road just below it, or null. Never build on a road tile.
- `town.addBuilding({ kind, name, w, h, color, ...more })`: places it (at `findSpot` unless you give `x, y`),
  returns the building or null. `town.buildingsOf(kind)`, `town.building(id)`.
- `town.drawBuilding(ctx, b, { roof, wall, sign })`: the standard look; a part draws its own buildings.
- `town.addPerson({ name, home, color, ...more })`, `town.walkTo(person, x, y, doing)`: walks along roads and grass.
- `town.findPath(fx, fy, tx, ty)`, `town.event(kind, text)`, `town.part(name)`.
- `town.advance(hours)`: runs time forward at once (tests). `town.summary()`: a short reading of the town.
- `town.errors`: errors thrown inside a part's init, tick or draw. It must stay empty.

## How a change is judged

The page is opened in a browser with `?test` (no animation), `town.start` runs every part's `init`, then the
job's check runs: a function body given `town`, which returns true only if the feature really happens, for
example `town.advance(24); return town.buildingsOf('bakery').length === 1 && town.state.events.some(e => e.kind === 'bread')`.
Also: no error while loading or while running two days, nothing in `town.errors`, the picture not blank, and
every check of every feature already kept (in `checks.json`) still true.

`node check.js` runs the same thing without a browser: `node check.js` (load, two days, every kept check) and
`node check.js job-check.js` (also the job's own check).
