How Ola worksWhere your work runs, what can leave the machine, and what gets written down. For you, and for the friend you ask whether this is safe.

Where things stand, November 19, 2026. Ola runs on a test machine today, with made-up data only. The Ola machine itself arrives about December 1, and real projects start on it in December. Each part below says whether it is live now or planned.

1Two places your work can run

LiveOn the Ola machine. You sign in at app.ola.cx, in a browser, the Mac app or the iPhone app. Your project’s files and the agent that works on them live on the Ola machine, one computer in an office. You see the same project and the same conversations from every device.

LiveOn your Mac. In the Mac app, or with the ola command in a terminal, the agent runs on your own Mac, in a folder you choose. Your files stay on your Mac. Only the requests to the model, and web searches, go to the Ola machine. The iPhone app can also connect to your Mac, over a private network.

2One sealed computer for each project

Live, test machineOn the Ola machine, each project gets its own virtual machine: a separate computer made in software. It holds that project’s files and its database, and nothing from any other project.

  • It has no internet connection at all.
  • Its system files can’t be changed, and the programs in it run without administrator rights.
  • The agent works inside it. It reads your documents, runs code, and makes tables, charts and pages there.
  • A project left alone for 30 minutes is stopped. It starts again in a few seconds when someone opens it.

This matters because documents can carry hidden instructions. A web page or a PDF can tell an AI agent to “send this file somewhere.” In a sealed computer there is nowhere to send it, except through the one gate below.

3The one way out: the model gateway

LiveEach project’s computer has exactly one way out. It leads to the model gateway, a small program on the Ola machine. The gateway holds the keys to the models, so a project never sees them. A pass taken from one project doesn’t work through another project’s gate.

  • What passes through: the agent’s requests to the model (your question, and the parts of your files it is reading), and the web searches and downloads that were allowed.
  • What it checks: which project is asking, the size of each request, how long it runs, and a weekly allowance for each project.
  • What it writes down: one line per request, with numbers only. Which project, which model, how many words in and out (counted in tokens), how long it took, whether it worked. Never the words of a request or a reply.
  • It rebuilds every answer from a short, fixed list of fields, so nothing extra from a model company reaches your project.

4Where your files and data live

LiveOn the Ola machine, everything about a project is on that project’s own disk, inside its sealed computer: the files you upload, what Ola downloads from the web, what Ola makes, and the conversations. Each project has its own database, one file, with your documents searchable page by page and every table Ola builds. Delete a project and its database goes with it.

You can see all of it. Files lists every file. Data shows every table, where it came from and how many rows it has. You can download the whole database as one file, or any table as a spreadsheet.

A separate, small sign-in database holds who may sign in, the teams, the projects and the activity log. It holds no file names, no file contents and nothing you wrote. A file appears there only as a scrambled fingerprint.

LiveOn your Mac, your files stay in the folder you chose.

5Signing in, and who can see a project

LiveYou sign in with a name and a password. Accounts are by invitation only. A passkey is optional. Sign-in sessions are kept without your IP address or browser details.

Each project belongs to a team, with three roles:

  • Owner: everything, including the project’s settings and publishing.
  • Member: reads, uploads, deletes, and asks Ola to work.
  • Viewer: reads only.

To anyone outside the team, the project doesn’t exist: they get the same answer as for a project that was never made. Removing someone takes effect on their next click, and cuts any connection they still have open.

The activity log records sign-ins, files uploaded, downloaded and deleted, files Ola read during its work, and every time work was shown to an outside model. The team can read its own project’s log.

One person runs the machine, and that person can, in principle, reach anything on it. That is what the letter means by “one machine and one person.” The tools for running the machine show counts, such as how many tables and documents a project has, not what is in them.

6Which model answers

Ola’s own open model comes first. An open model is an AI model anyone can download and run on their own computer.

Live, made-up dataToday, while the test machine holds only made-up data, the open models are rented from Together AI, an outside company.

Planned, DecemberFrom December they run on the Ola machine itself, so your words don’t leave it.

LiveTwo fallbacks, both off until the project’s owner turns them on: a larger open model at an outside company (Together AI today), and Claude, from Anthropic. When one is used, your request and the parts of your files Ola reads to answer it go to that company.

  • The owner turns each one on after reading what it sends and where. They can turn it off at any time. A member can’t turn them on.
  • Ola may suggest a fallback when a job looks too big for its own model. Nothing goes unless the owner has said yes, either for that one request or in the project’s settings (only when asked, when Ola gets stuck, or always).
  • Every use is marked in the conversation and written in the activity log. Each project has a monthly spending limit for them.
  • Claude works inside the same sealed computer, and its requests pass through the same gateway.

The order is always the same: Ola’s own model, then a hosted open model, then Claude, each only when the one before isn’t good enough.

7Web search and downloads

LiveA project’s computer can’t reach the web. When Ola needs to search or download, it asks the gateway, which does it and hands back the result.

  • The words of a search go to Brave Search. Nothing from your files goes with them.
  • With “Lots of permissions” on (the default), Ola searches and downloads without asking each time. With it off, Ola asks first: Allow once, Always in this project, or Not now.
  • “Always” shows in the project’s Settings, with who chose it and when, and can be taken back there.
  • Everything downloaded stays in the project, with the address it came from.

8Publishing

LiveNothing Ola makes is public until the project’s owner presses Publish. The agent itself has no way to publish.

  • The Publish sheet lists exactly which files will be public, and the address: sites.ola.cx, in a folder for the project.
  • Before anything leaves, every file is checked. A publish is refused if a file holds a password or a key, is a database, or is a file of secrets.
  • Published pages are plain files, served by Vercel, a hosting company, not from the Ola machine.
  • Unpublish takes them down.

9Encryption and backups, as they are today

LiveOn the way. Everything between your device and app.ola.cx is encrypted (HTTPS). The encryption ends on the Ola machine itself. The relay that carries traffic in from the internet passes it on still encrypted, and can’t read it.

TodayOn the disk. The test machine holds only made-up data, and its disk is not encrypted.

Planned, DecemberThe Ola machine will have full-disk encryption turned on before any real project arrives. It will also run under a separate account that only owns the projects. The test machine never holds real data.

TodayBackups. There are no automatic backups yet. A project can be copied and restored by hand, and that is tested.

PlannedEncrypted backups. Once they run, a file you delete leaves the project at once and stays in the encrypted backups for up to 14 days.

LiveDeleting. A deleted file leaves the project at once. Deleting a project removes its disk and its database.

10What Ola does not do

  • It doesn’t send your files to an AI company unless your project’s owner says yes. Every time it does, it says so.
  • It doesn’t train AI models on your work.
  • It doesn’t put the words of your requests or its replies in any log.
  • It doesn’t give a project’s computer an internet connection.
  • It doesn’t publish anything the owner didn’t choose to publish.
  • Its pages on ola.cx load nothing from any other website: no ads, no trackers, no analytics.
  • It isn’t bulletproof. It is one machine, run by one person. It can’t protect your work from that person, or from someone who breaks into the machine. What it can do is keep your work in one place you can see, and let you delete it.
