2. Voice first, text as a drawer

The study sheet you already built is Infinity Chat — so make it the screen, not a sheet over a chat window. Voice, the clean-up walk, cards and quizzes are the app. Text chat becomes one drawer, reachable from every screen with the same button, with two modes: Scrivi (practice in Italian) and Chiedi a Polly (tell the agent what to do). The text thread is never the container; it's a tool you pull up.

The one rule
Every screen is a place; the text drawer is a tool you bring to it. The drawer always knows where you opened it (this topic, this chat, this card, this lesson), so "make 20 cards about food" or "why anch'io and not anche io?" needs no preamble. Close it and you're back exactly where you were.

Infinity Chat home and one chat

Two screens replace the chat window + study sheet pair. The home is a journey; a chat is a page with sections, not four buttons.

What changes, concretely

In the app

  • Routing. A topic of kind infinity pushes InfinityHomeView directly from Topics — not TopicDetailView. InfinityChatBar is deleted. The home stops being a .sheet.
  • Home layout. The talk card shrinks to a hero; the chat list becomes the vertical rail (PathList in PathViews.swift already draws this shape — reuse its node/line components). One status + at most one action per row.
  • New: InfinityChatPage. Sections: fixes, words, grammar, transcript; footer: Quiz / Continue. Vocab and grammar sheets (InfinityDrillViews) become the section drill-ins.
  • New: PollyDrawer. One SwiftUI half-sheet (.presentationDetents([.medium, .large])), a segmented control, and a DrawerContext enum (topic / chat / card / lesson / none). Presented by a shared PollyButton in every custom header. It hosts the existing chat message list + composer from TopicDetailView, so bubbles, streaming and tool cards are reused, not rebuilt.
  • Continue by voice = VoiceSessionView with the chat's transcript as context; the finish call appends to the same InfinityChat.
  • Lesson screens (path and guest) drop the chat underneath; LessonStepsCard / LessonCard become the screen body, with the Polly button in the header.

On the server

  • Two explicit lanes on the chat route, chosen by the client (mode: 'practice' | 'agent') — no language detection to get wrong. Practice: the conversation prompt, reply in the studied language at level, one folded fix max. Agent: agent.ts, terse, with a context block the drawer sends (topic id, chat id, card id, lesson id).
  • Typed practice → an Infinity chat. POST /infinity/chats accepts a message transcript as well as a voice_session_id; the clean-up (infinity.ts) already works on text.
  • Infinity tools for the agent: list_chats, rename_chat, cards_from_chats(n, focus), weak_spots(days) (the "what did I get wrong most" answer comes from fixes grouped by grammar point — the data is already there).
  • Continue a chat: the voice session route takes continue_chat_id; finish appends the fragments and re-runs the clean-up on the delta only.

Where it's strong, where it's weak

Strong

  • It looks like the product you're describing: a voice-first language app with cards, not a chat app with a language feature. Home is a journey, not a thread.
  • One consistent way to reach text from anywhere — the same button, the same drawer, on every screen. Text practice and agent admin both get a proper home without either owning the screen.
  • No ambiguity about who you're talking to: the segmented control decides, not a language detector.
  • Fixes the same disease elsewhere: the lesson screens stop sitting on an empty chat, and Peck's "Talk it through with Polly" becomes the drawer with the card as context.
  • Reuses what exists: the study sheet's cards, the path rail, the chat view inside the drawer, the clean-up walk.

Weak

  • More surgery: a new routing rule, a new page, a new shared drawer, and two lesson screens to re-lay. Bigger than Direction 1.
  • The history of what you asked Polly to do lives in the drawer per context, not in one visible thread. If you value scrolling back through "I asked for cards on Tuesday", this hides it.
  • Text practice in a half-sheet is a smaller canvas than a full chat screen. (Mitigation: the drawer expands to .large on first keystroke.)
  • Two modes is a UI concept to learn, even if it's one control.

Open questions

  • Does the drawer remember its thread per context (this topic's admin history) or is it one global agent thread with context injected? Drawn: per context, because "rename this" needs a this.
  • Should Scrivi live in the drawer at all, or should a typed practice session be a full screen you start from the hero ("Start a chat" → speak or type)? The drawer is drawn because it's reachable from anywhere; the full screen would be calmer for long practice.
  • Is "Continue" on a mastered chat allowed to un-master it? Drawn: yes, the new part gets its own fixes and the badge returns after the next quiz.
